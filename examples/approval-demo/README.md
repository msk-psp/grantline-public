# 로컬 승인 시험실

GitHub 계정을 새로 만들거나 Slack·GitHub 토큰을 준비하지 않고 승인 화면과 처리 흐름을 시험합니다.
저장소 루트에서 Python 3.11 이상으로 실행하세요. 추가 패키지는 필요 없습니다.

```bash
python3 examples/approval-demo/run.py
```

표시된 **http://127.0.0.1:8422/demo**를 엽니다. 포트가 사용 중이면 `--port 8424`처럼 지정합니다.
기존 8421 콘솔과 별도로 실행하며 외부에서 접속할 수 있는 bind 옵션은 없습니다.

1. **요청자로 전환** → **샘플 권한 요청** → 미리보기의 승인 요청 버튼으로 제출합니다.
2. **역할 전환·알림함**으로 돌아오면 **모의 Slack 알림함**에 승인 링크가 나타납니다.
3. **승인자로 전환**한 뒤 알림의 **승인 요청 열기**를 누르고 승인 또는 거절합니다.
4. 승인하면 **시뮬레이션 PR**에서 승인한 변경 내용을 확인합니다. 거절하면 PR은 만들어지지 않습니다.

자기 승인 거부도 확인할 수 있습니다. 요청자 역할을 유지한 채 승인 버튼을 누르면 거부됩니다.
샘플을 여러 번 제출할 수 있고, 서버를 종료하고 다시 실행하면 모든 기록이 초기화됩니다.
종료는 `Ctrl-C`입니다. 실행 상태는 저장소 밖의 임시 디렉터리에 보관합니다.

## 검증 범위

실제 Grantline의 프록시 신원 처리, 요청 저장, 지정 승인자 확인, 자기 승인 거부,
승인 계획 고정, writer 호출, `proposed` 상태 전환과 화면을 사용합니다.
샘플 대상은 가상 `demo-user`의 `bucket:demo/team` 읽기 요청 하나입니다.

가상 로그인 선택기가 헤더를 설정하고, 알림은 로컬 알림함에만 기록하며, writer는
실제 GitHub PR 대신 로컬 변경 문서를 만듭니다. 화면의 PR 링크도 그 문서로 연결됩니다.
서버 프로세스에 외부 토큰 환경변수를 전달하지 않고, native S3 어댑터는 읽기 전용 fixture를 사용합니다.

**이 환경의 성공은 실제 Slack 전달, GitHub SSO, GitHub PR 생성 또는 S3 접근 성공을 뜻하지 않습니다.**
운영 인증 설정을 변경하지 않습니다. 이 도구를 서버나 공유 프록시 뒤에 배포하지 마세요.
실제 연동 시험은 별도 제한된 저장소·계정·경로와 자격증명을 준비한 뒤 진행합니다.
